## 1. Qwen-VL官方蒸馏方案详解

### 1.1 整体蒸馏链路

```
原始图片库 → 32B教师两阶段推理 → 多层过滤清洗 → 构建蒸馏数据集 → 轻量化学生模型联合训练
     ↓              ↓                   ↓                ↓                    ↓
   车载图片      阶段1: 硬+软标签      置信度过滤        三层损失联合          QLoRA微调
                 阶段2: CoT生成        一致性校验        CE+KL+SFT
                                      语义过滤
                                      全局去重
```

### 1.2 三层损失设计（官方核心）

| 损失类型 | 监督来源 | 训练目标 | 作用 |
|----------|----------|----------|------|
| **CE Loss（硬标签）** | 教师硬标签答案 | 强制最终答案匹配教师预测 | 确保答案准确 |
| **KL Loss（软标签）** | 教师全类别概率分布 | 复刻教师的细微区分能力 | 处理模糊/遮挡样本 |
| **SFT Loss（CoT）** | 教师生成的推理文本 | 学习分步看图推理 | 减少视觉幻觉 |

**损失组合策略**：
- 三种损失加权求和：`L_total = α·L_CE + β·L_KL + γ·L_SFT`
- 权重根据任务类型动态调整
- CE Loss权重最高，确保答案正确性

### 1.3 两阶段推理生成逻辑

#### 阶段1：生成硬标签 + 软标签（无CoT）

**输入**：
- 图片
- 问题
- 闭合候选集：`allowed_answers = [zero, one, two, red, white, yes, no]`

**推理过程**：
1. 输入极简分类Prompt，无长推理约束
2. 模型前向传播，获取语言头完整logits
3. **过滤逻辑**：只保留allowed_answers内对应token的logits
4. 对筛选后的logits执行softmax，得到`soft_dist`
5. 取概率最大值作为`hard_label`，最大值为`confidence`

**阶段1输出示例**：
```json
{
  "question": "How many people wear headphones?",
  "allowed_answers": ["zero", "one", "two"],
  "hard_label": "one",
  "soft_dist": {"zero": 0.05, "one": 0.92, "two": 0.03},
  "confidence": 0.92
}
```

#### 阶段2：复用阶段1标签，生成结构化CoT

**输入**：
- 阶段1的全部结果（allowed_answers、primary_answer、soft_dist）
- 图片和问题

**推理过程**：
1. 将阶段1结果注入system Prompt作为约束
2. 强制模型按固定三段输出：Observation / Analysis / Conclusion
3. **规则约束**：
   - 禁止appear/seem/guess类推测词
   - 禁止markdown符号
   - 遮挡物体必须写"cannot recognize"
4. 自回归生成推理文本，提取三段内容

**阶段2合并完整样本**：
```json
{
  "img_path": "./car_001.jpg",
  "question": "How many people wear headphones?",
  "allowed_answers": ["zero", "one", "two"],
  "hard_label": "one",
  "soft_dist": {"zero": 0.05, "one": 0.92, "two": 0.03},
  "confidence": 0.92,
  "cot": {
    "observation": "One audience member's headphones are fully visible; other people's ear areas are blocked.",
    "analysis": "Only the clearly visible person meets the counting standard, blocked areas cannot be counted.",
    "conclusion": "Final Answer: one"
  }
}
```

### 1.4 Token过滤机制（两层设计）

#### 层级1：推理生成时stop_words实时拦截

**配置禁止token列表**：
- **Markdown类**：`*`, `#`, `-`, `{`, `}`, `` ` ``
- **模糊推测词汇**：appear, seem, probably, likely, suggest
- **非法数字token**：`1`, `2`, `3`（强制输出单词）

**实时拦截机制**：
- 模型一旦生成禁止字符，立刻截断输出
- 设置`repetition_penalty=1.2`抑制重复语句

#### 层级2：后处理文本token清洗

- 正则清除所有剩余特殊符号、连续换行、多余空格
- 裁剪冗余描述token（过滤无关背景词汇）
- **长度过滤**：
  - Observation token数 < 15：标记低质样本
  - CoT总token > 350：描述冗余，丢弃
- **非法词汇匹配**：出现禁用推测词，直接标记脏样本

### 1.5 四层数据清洗逻辑

#### 第一层：置信度过滤（阶段1直接丢弃）

- **阈值**：confidence < 0.7
- **效果**：模糊、强光遮挡、目标看不清的难样本提前过滤
- **收益**：节省CoT推理算力消耗

#### 第二层：闭合答案一致性校验

- 抽取CoT内`Final Answer`后的词汇
- 与`hard_label`字符串严格比对
- **不一致**：标记冲突脏样本，直接剔除
- **解决**：推理文字和最终答案矛盾问题

#### 第三层：文本Token & 语义过滤

- **重复度校验**：Observation与Analysis余弦相似度 > 0.9，丢弃
- **遮挡规则校验**：目标被遮挡但文本写"fully exposed"，过滤
- **停用词过滤**：存在禁止推测词、阿拉伯数字、markdown符号，剔除

#### 第四层：离线全局去重

- **图像哈希去重**：重复图片只保留1条标注
- **异常分布过滤**：soft_dist所有类别概率差距极小（熵过高），删除

### 1.6 三级兜底容错策略

#### 1. 推理运行时异常兜底

| 异常类型 | 处理策略 |
|----------|----------|
| **OOM显存溢出** | 捕获异常，跳过当前图片，写入错误日志，继续下一张 |
| **图像损坏/读取失败** | 跳过样本，记录坏图路径，人工复核 |
| **模型生成空文本** | 重试最多2次，仍为空则丢弃 |

#### 2. 模型输出幻觉兜底

- **遮挡检测**：目标大面积遮挡但未写"cannot recognize"，标记低分
- **闭合集校验**：输出答案超出allowed_answers，强制丢弃
- **幻觉日志**：批量推理记录幻觉样本ID，定期人工筛选

#### 3. 数据集训练兜底

- **训练时二次校验**：过滤残留脏样本
- **Loss监控**：单批次loss异常飙升，自动回溯剔除异常标注
- **断点保存**：每轮保存LoRA权重，崩溃可恢复

## 2. 整体方案架构对比

### 2.1 核心架构差异

| 维度 | 当前项目 | Qwen-VL官方 | 关键差异 |
|------|----------|--------------|----------|
| **蒸馏链路** | 两阶段推理（Hard+Soft / CoT） | 两阶段推理（Hard+Soft → CoT） | **一致** |
| **软标签来源** | 温度缩放softmax(logits) | 闭合集logits过滤后softmax | **差异1**：官方有闭合集约束 |
| **硬标签确定** | 软分布最大值 | 软分布最大值 | **一致** |
| **CoT生成** | 单独推理，结构化输出 | 复用阶段1标签作为约束 | **差异2**：官方约束更严格 |
| **置信度过滤** | 入口拦截（<0.4跳过） | 入口拦截（<0.7跳过） | **差异3**：官方阈值更严格 |
| **训练方式** | 数据生成为主 | 三层损失联合训练（CE+KL+SFT） | **差异4**：官方有完整训练框架 |

### 2.2 链路流程对比

#### 当前项目流程：
```
图片+问题
    ↓
推理1: Standard Prompt → hard_label + soft_label（含logits）
    ↓（置信度 >= 0.4）
推理2: CoT Prompt → cot_reasoning（使用primary_answer + allowed_answers）
    ↓
保存合并结果
    ↓
后处理：数据清洗 → 质量检验
```

#### Qwen-VL官方流程：
```
图片+问题+allowed_answers
    ↓
阶段1: 极简Prompt → logits → 闭合集过滤 → soft_dist → hard_label + confidence
    ↓（置信度 >= 0.7）
阶段2: 注入阶段1结果作为约束 → 三段式CoT → Final Answer校验
    ↓
四层清洗：置信度 → 一致性 → 语义 → 去重
    ↓
训练：CE + KL + SFT三层损失
```

### 2.3 核心差异总结

| 差异点 | 当前项目 | Qwen-VL官方 | 影响 |
|--------|----------|--------------|------|
| **闭合候选集** | 无强制约束 | 强制allowed_answers约束 | 官方软标签更精准 |
| **置信度阈值** | 0.4（宽松） | 0.7（严格） | 当前保留更多数据，但质量可能更低 |
| **CoT一致性校验** | 无 | 强制Final Answer与hard_label一致 | 官方避免推理冲突 |
| **训练框架** | 仅数据生成 | 完整三层损失训练 | 当前缺少训练时蒸馏设计 |

## 3. Prompt生成深度对比

### 3.1 当前项目Prompt设计

**Standard Prompt**：
```
{question}
Answer in one word:
```

**CoT Prompt（System）**：
```
TASK: Answer by selecting ONE answer from the allowed list.
RULES:
1. Observation: Only describe features that distinguish answers
2. Analysis: Compare candidates using probability distribution
3. Conclusion: Output ONE answer from allowed list
FORMAT: Observation: [visual features]
Analysis: [reasoning with probabilities]
Conclusion: [one answer]
```

**特点**：
- ✅ 32B模型优化：提示词简洁
- ✅ 无markdown：减少格式干扰
- ⚠️ 缺少闭合集约束（allowed_answers为软约束）

### 3.2 Qwen-VL官方Prompt设计

**阶段1 Prompt（极简分类）**：
```
Question: {question}
Allowed answers: {allowed_answers}
Answer:
```

**阶段2 Prompt（注入约束）**：
```
System: You must answer from: {allowed_answers}
Primary candidate: {primary_answer}
Distribution: {soft_dist}

Rules:
- Write: Observation / Analysis / Conclusion
- No: appear/seem/probably/maybe
- No markdown symbols: * # -
- For blocked objects: write "cannot recognize"

Question: {question}
Answer step by step:
```

**特点**：
- ✅ **闭合集硬约束**：直接在Prompt中限定答案范围
- ✅ **概率注入**：将soft_dist作为上下文，引导推理方向
- ✅ **禁用词列表**：明确禁止推测性词汇
- ✅ **遮挡规则**：强制要求标注遮挡情况

### 3.3 Prompt差异分析

| 维度 | 当前项目 | Qwen-VL官方 | 优化建议 |
|------|----------|--------------|----------|
| **闭合集约束** | 软约束（allowed_answers可选） | 硬约束（强制限定） | 应采用硬约束 |
| **概率注入** | 不注入soft_dist | 注入soft_dist作为提示 | 可提升CoT准确性 |
| **禁用词规则** | 无明确规则 | 明确禁止推测词 | 应加入禁用词列表 |
| **遮挡处理** | 无特殊规则 | 强制标注"cannot recognize" | 应加入遮挡规则 |
| **stop_words** | 无实时拦截 | 推理时实时拦截禁止token | 应加入实时拦截 |

## 4. 三种标签生成逻辑对比

### 4.1 硬标签生成对比

#### 当前项目实现：

**流程**：
1. Standard Prompt推理
2. 获取完整logits
3. Temperature缩放后softmax
4. 取最大概率对应的token作为answer
5. 最大概率值作为confidence

**问题**：
- ❌ 无闭合集约束，可能输出意外token
- ❌ logits过滤在后处理阶段，非推理阶段

#### Qwen-VL官方实现：

**流程**：
1. 极简Prompt（含allowed_answers）
2. 获取完整logits
3. **关键差异**：只保留allowed_answers对应的token logits
4. 对筛选后的logits执行softmax
5. 取最大概率作为hard_label

**优势**：
- ✅ 闭合集约束，确保答案在候选范围内
- ✅ 过滤在softmax前，避免干扰概率分布

### 4.2 软标签生成对比

#### 当前项目实现：

**流程**：
1. 从hard_label获取logits
2. Temperature=4缩放
3. **四层过滤**：
   - Layer 1: 黑名单过滤
   - Layer 2: 硬标签保护
   - Layer 3: Top-K兜底
   - Layer 4: 任务适配过滤
4. 词干归一化
5. 等价token合并

**特点**：
- ✅ 多层过滤，质量可控
- ⚠️ 过滤在后处理，可能丢失原始分布信息
- ⚠️ temperature固定为4，未考虑置信度

#### Qwen-VL官方实现：

**流程**：
1. 从阶段1获取完整logits
2. **闭合集过滤**：只保留allowed_answers对应的logits
3. 对筛选后的logits执行softmax
4. 直接得到soft_dist（无需额外过滤）

**特点**：
- ✅ 过滤在softmax前，保留原始分布信息
- ✅ 无需后处理过滤，流程简洁
- ⚠️ 依赖allowed_answers的准确性

### 4.3 CoT生成对比

#### 当前项目实现：

**流程**：
1. 使用soft_label的primary_answer和allowed_answers作为约束
2. 单独推理生成CoT
3. 结构化输出：Observation/Analysis/Conclusion
4. 质量验证：检查关键词、长度

**问题**：
- ❌ 无强制一致性校验（CoT结论可能与hard_label不同）
- ❌ 无禁用词实时拦截
- ❌ 无遮挡规则约束

#### Qwen-VL官方实现：

**流程**：
1. **注入阶段1结果**：allowed_answers、primary_answer、soft_dist全部注入Prompt
2. 强制三段输出：Observation/Analysis/Conclusion
3. **禁用词拦截**：推理时实时拦截推测词、markdown符号
4. **遮挡规则**：遮挡物体必须写"cannot recognize"
5. **一致性校验**：Final Answer必须与hard_label一致

**优势**：
- ✅ 强制一致性校验，避免推理冲突
- ✅ 禁用词实时拦截，减少幻觉
- ✅ 遮挡规则，提升推理质量

### 4.4 核心差异总结

| 标签类型 | 当前项目 | Qwen-VL官方 | 核心差异 |
|----------|----------|--------------|----------|
| **硬标签** | 后处理过滤 | 推理时闭合集约束 | 官方更精准 |
| **软标签** | 四层后处理过滤 | 推理时闭合集过滤 | 官方保留原始分布 |
| **CoT** | 无强制校验 | 强制一致性+禁用词拦截 | 官方质量更高 |

## 5. Token过滤机制逐项对比

### 5.1 层级1：推理生成时stop_words实时拦截

> **核心原理**：在模型推理过程中，一旦检测到禁止token立即截断输出，从源头控制生成质量

#### 5.1.1 功能实现状态对比

| **模糊推测词拦截** | appear, seem, probably, likely, suggest | ❌ 未实现 | ✅ 已实现 | **缺失** |

### 5.2 层级2：后处理文本token清洗

> **核心原理**：在推理完成后，对生成的文本进行清洗和过滤

#### 5.2.1 功能实现状态对比

#### 1. 推理运行时异常兜底

| 异常类型 | 处理策略 |
|----------|----------|
| OOM显存溢出 | 捕获异常，跳过当前图片，写入错误日志，继续下一张 |
| 图像损坏/读取失败 | 跳过样本，记录坏图路径，人工复核 |
| 模型生成空文本 | 重试最多2次，仍为空则丢弃 |

#### 2. 模型输出幻觉兜底

| 幻觉类型 | 处理策略 |
|----------|----------|
| 遮挡幻觉 | 目标大面积遮挡但未写"cannot recognize"，标记低分 |
| 闭合集违反 | 输出答案超出allowed_answers，强制丢弃 |
| 幻觉日志 | 批量推理记录幻觉样本ID，定期人工筛选 |

#### 3. 数据集训练兜底

| 兜底机制 | 说明 |
|----------|------|
| 训练时二次校验 | 过滤残留脏样本 |
| Loss监控 | 单批次loss异常飙升，自动回溯剔除异常标注 |
| 断点保存 | 每轮保存LoRA权重，崩溃可恢复 |

### 7.3 容错机制差异分析

| 维度 | 当前项目 | Qwen-VL官方 | 优化建议 |
|------|----------|--------------|----------|
| **OOM处理** | 无自动跳过 | 捕获并跳过 | 应加入OOM捕获 |
| **空输出重试** | 无 | 重试2次 | 应加入重试机制 |
| **遮挡幻觉检测** | 无 | 有 | 应加入遮挡规则 |
| **训练时兜底** | 无 | Loss监控+断点保存 | 应加入训练兜底 |

## 8. 训练损失设计对比

### 8.1 当前项目训练设计

**现状**：
- 仅生成蒸馏数据，未设计训练框架
- 无三层损失设计
- 无QLoRA微调方案

### 8.2 Qwen-VL官方训练设计

**三层损失联合训练**：

#### 损失组合：
```
L_total = α·L_CE + β·L_KL + γ·L_SFT
```

| 损失类型 | 监督来源 | 目标 |
|----------|----------|------|
| **CE Loss** | 教师硬标签 | 强制答案匹配 |
| **KL Loss** | 教师软标签分布 | 复刻细微区分能力 |
| **SFT Loss** | 教师CoT文本 | 学习分步推理 |

#### 训练方式：
- **QLoRA低秩微调**：无需全参数更新
- **硬件要求**：单A6000即可训练7B/14B模型
- **数据区分**：
  - 推理数据：仅给32B教师打标
  - 训练数据：清洗后的标注集，输入学生模型

### 8.3 训练设计差异分析

| 维度 | 当前项目 | Qwen-VL官方 | 优化建议 |
|------|----------|--------------|----------|
| **训练框架** | 无 | 完整三层损失 | 应设计训练框架 |
| **KL蒸馏** | 无 | 有（软标签KL Loss） | 应加入KL蒸馏 |
| **CoT SFT** | 无 | 有（推理文本SFT） | 应加入CoT SFT |
| **QLoRA** | 无 | 有（低秩微调） | 应设计QLoRA方案 |

## 9. 关键差异与优化建议

### 9.1 核心差异总结

| 维度 | 当前项目 | Qwen-VL官方 | 差异影响 |
|------|----------|--------------|----------|
| **闭合集约束** | 软约束（后处理） | 硬约束（推理时） | 官方软标签更精准 |
| **置信度阈值** | 0.4（宽松） | 0.7（严格） | 当前保留更多但质量可能更低 |
| **Token过滤时机** | 全部后处理 | 推理时+后处理 | 官方可实时干预推理 |
| **CoT一致性校验** | 无 | 强制校验 | 官方避免推理冲突 |
| **禁用词拦截** | 无 | 实时拦截 | 官方减少幻觉 |
| **遮挡规则** | 无 | 强制标注 | 官方推理质量更高 |
| **训练框架** | 仅数据生成 | 三层损失训练 | 当前缺少训练设计 |

### 9.2 高优先级优化建议

#### 1. **引入闭合集约束（关键）**

**当前问题**：
- allowed_answers仅作为软约束
- logits过滤在后处理，可能引入噪音token

**优化方案**：
- 在阶段1推理前，预设闭合候选集allowed_answers
- 在softmax前，只保留allowed_answers对应的token logits
- 确保软标签分布仅包含有效候选

**预期收益**：
- 软标签更精准，减少噪音token
- 硬标签更有保障，答案必在候选集内

#### 2. **提高置信度阈值至0.5-0.6**

**当前问题**：
- 阈值0.4过低，保留大量低质量样本
- 低质量样本影响CoT生成质量

**优化方案**：
- 提高入口拦截阈值至0.5-0.6
- 对低置信度样本可选择性保留（标注低质量）
- 参考：Qwen-VL官方阈值0.7

**预期收益**：
- 减少无效CoT推理，节省算力
- 提升整体数据质量

#### 3. **加入推理时stop_words拦截**

**当前问题**：
- Token过滤全部在后处理，无法干预推理过程
- 模型可能生成markdown符号、推测词等

**优化方案**：
- 配置stop_words列表：
  - Markdown：`*`, `#`, `-`, `{`, `}`, `` ` ``
  - 推测词：appear, seem, probably, likely, suggest
  - 非法数字：`1`, `2`, `3`
- 在teacher_model推理时设置stop_strings参数

**预期收益**：
- 实时拦截禁止token，减少幻觉
- 提升CoT质量

#### 4. **加入CoT一致性校验**

**当前问题**：
- CoT的Conclusion可能与hard_label不一致
- 推理过程和最终答案矛盾

**优化方案**：
- 提取CoT的Conclusion部分（"Final Answer:"后的词汇）
- 与hard_label严格比对
- 不一致则标记或剔除

**预期收益**：
- 避免推理冲突，提升数据质量

#### 5. **设计三层损失训练框架**

**当前问题**：
- 仅生成数据，未设计训练框架
- 无KL蒸馏和CoT SFT

**优化方案**：
- 设计三层损失：`L = α·L_CE + β·L_KL + γ·L_SFT`
- 硬标签CE Loss：确保答案正确
- 软标签KL Loss：复刻教师分布
- CoT SFT Loss：学习推理过程

**预期收益**：
- 完整的蒸馏训练流程
- 提升student模型性能

### 9.3 中优先级优化建议

| 优化项 | 具体改进 | 预期收益 |
|--------|----------|----------|
| **遮挡规则** | 强制标注"cannot recognize" | 减少遮挡幻觉 |
| **动态温度** | 根据置信度自适应调整temperature | 高置信度更sharp，低置信度更smooth |
| **语义过滤** | 检测Observation/Analysis相似度 | 过滤重复描述 |
| **OOM兜底** | 捕获显存溢出，自动跳过 | 提升鲁棒性 |
| **空输出重试** | 重试2次 | 减少丢数据 |
