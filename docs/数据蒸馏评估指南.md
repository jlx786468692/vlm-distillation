# 数据蒸馏评估指南

> 本文档说明 VLM 蒸馏项目（`vlm-distillation`）中学生模型相对教师模型的**评估体系**：评估什么、每个指标如何计算、代码出处、以及如何解读结果。
>
> 评估代码位于 [src/evaluation/](../src/evaluation/)，入口 [evaluator.py](../src/evaluation/evaluator.py) `run_evaluation()`，由流水线 `evaluation` 步骤调用，报告写入 `outputs/evaluation/report.json`。

---

## 1. 评估总览

### 1.1 评估目标

蒸馏是把大教师（32B / agent_distill 教师）的"推理 + 答案"能力压到小学生（Qwen2.5-VL-3B）里。评估回答两个问题：

1. **学生学没学到教师的精髓？**（蒸馏质量）—— 学生输出 vs 教师标签，覆盖答案准确率、推理文本相似度、序列似然、软标签分布形状。
2. **学生在真实约束下能不能用？**（部署效率 + 场景准确率）—— 参数量 / 显存 / 延迟 / 吞吐，以及按题型分桶的绝对准确率（学生 vs 人工 ground truth）。

### 1.2 三维度结构

`run_evaluation` 依次运行三个维度，各自独立产出指标，聚合进 `report.json["dimensions"]`：

| 维度 | 模块 | 默认 | 核心问题 |
|---|---|---|---|
| **distillation_quality** | [distillation_quality.py](../src/evaluation/distillation_quality.py) | enabled | 学生 vs 教师：答案对不对、推理像不像、分布学没学到 |
| **driving_scenario** | [driving_scenario_eval.py](../src/evaluation/driving_scenario_eval.py) | **disabled** | 学生 vs COCO 人工 GT 的场景分桶准确率（已并入维度一，独立维度默认关） |
| **deployment_efficiency** | [deployment_efficiency.py](../src/evaluation/deployment_efficiency.py) | enabled | 部署相关：参数/显存/延迟/吞吐 |

> **注意**：原 `driving_scenario` 维度会独立跑一轮学生生成 + 查 COCO 标注表，耗时翻倍。现已把"学生 vs 记录自带 `ground_truth` 字段"的场景分桶准确率**并入维度一**（复用同一轮生成，零额外开销，见 [§4.7](#47-scenario_buckets-场景分桶绝对准确率)）。独立 `driving_scenario` 维度默认 `enabled: False`，仅当需要用 COCO `(image_id, question)` 查表而非记录自带 GT 时才开。

### 1.3 评估数据流

```
configs/default.yaml [evaluation]
   │
   ├─ eval_data_path  ──► held-out 评估集（教师标签 jsonl，如 32b val 336 条）
   │     └─ 不存在则回退 train_data_path（训练集）并告警"无 held-out，指标高估"
   ├─ student_model_path ─► ./outputs/student_merged（merged 全权重）
   ├─ images_root ─────► ./data/filter_coco/images/val2014
   └─ dimensions.* ────► 各维度开关与超参

run_evaluation(cfg)
   1. _load_records(eval_data_path, max_samples) → 教师标签记录列表
   2. StudentInferencer(model_path, ...) 加载学生（贪婪推理）
   3. 依次 eval_distillation_quality / eval_driving_scenario / eval_deployment_efficiency
   4. _save_report → outputs/evaluation/report.json
```

**held-out 判定**（[evaluator.py:387-396](../src/evaluation/evaluator.py#L387)）：`eval_data_path` 指向的文件存在 → `is_heldout=True`（真泛化评估）；否则回退训练集并打印告警。`report.json` 里 `is_heldout` 字段标注。

## 2. 教师标签记录格式（评估输入）

每条记录是一个扁平 dict（训练 JSONL 同源），评估依赖以下字段：

| 字段 | 闭集 | 开集 | 用途 |
|---|---|---|---|
| `image_path` / `image_id` | ✓ | ✓ | 定位图像（[§3.2](#32-图像与路径解析)） |
| `question` | ✓ | ✓ | 学生输入 |
| `question_type` | yes_no/counting/color/choice/... | open_descriptive | 分桶、闭/开判定 |
| `question_category` | closed / None | open | 开集判定（可空） |
| `hard_label.answer` | ✓ | — | 教师短答案（闭集 GT） |
| `soft_label.answer_distribution` | ✓ {答案:prob} | — | 软标签分布（KL 匹配） |
| `soft_label.primary_answer` | ✓ | — | 教师 top-1 答案 |
| `cot_reasoning.reasoning_paragraph` | ✓ | ✓ | 教师推理段（CoT 相似度） |
| `cot_reasoning.answer` | — | ✓ | 教师开集答案 |
| `ground_truth` | ✓ | ✓ | 人工 GT（场景准确率） |

**闭集判定口径**（[distillation_quality.py:122](../src/evaluation/distillation_quality.py#L122)）：`is_closed = bool(soft_label.answer_distribution)`。**不**用 `question_category=="closed"`（教师标注 jsonl 里该字段常为 None，会导致全误判为 open、闭集指标归零）。这与训练侧 `DistillDataset` 对齐。

## 3. 学生推理器 StudentInferencer

[evaluator.py:76-154](../src/evaluation/evaluator.py#L76)。加载 merged 全权重学生，贪婪解码。

### 3.1 关键方法

| 方法 | 作用 | 输出 |
|---|---|---|
| `infer(image_path, question)` | 贪婪生成（`do_sample=False`, `max_new_tokens=256`） | 学生回答文本 |
| `sequence_ce(image_path, question, target_text)` | 学生对教师目标序列的自回归 NLL（单次 forward） | `(mean_ce, n_tokens)` |
| `sequence_ce_and_distribution(...)` | **合并前向**：序列 CE + 软标签分布匹配（一次 forward 算两指标） | `(ce, n_tok, dist_res)` |
| `count_parameters()` | 总参数 / 可训练参数 | `{total, trainable}` |

`sequence_ce_and_distribution` 是核心优化：序列 CE 需要对"prompt + 教师目标文本"做一次 forward，软标签分布匹配正好也在这次 forward 的"答案 token 位置"上抽 logits，两者共用一次前向，避免重复计算（[evaluator.py:213-314](../src/evaluation/evaluator.py#L213)）。

### 3.2 图像与路径解析

`_resolve_image`（[distillation_quality.py:271](../src/evaluation/distillation_quality.py#L271)）按优先级找图：
1. 记录里的 `image_path` 原值
2. `images_root / basename(image_path)`
3. `images_root / COCO_val2014_{image_id:012d}.jpg`

### 3.3 像素上限对齐

`max_pixels` / `min_pixels` 强制设到 `image_processor`（[evaluator.py:95-105](../src/evaluation/evaluator.py#L95)），**与训练侧一致**（默认 `max_pixels=100352` ≈ 128 视觉 token）。评估若用 Qwen 默认 802816（≈1024 视觉 token）会脱离训练分辨率，单条 forward 偏重且分布失真，故显式收紧。

### 3.4 LoRA 回退

若 `model_path` 指向 LoRA adapter 目录（非 merged 全权重），`from_pretrained` 失败后回退：加载 base（`models/Qwen2.5-VL-3B-Instruct`）+ `PeftModel.from_pretrained(adapter)`（[evaluator.py:113-124](../src/evaluation/evaluator.py#L113)）。正式评估建议用 merged 目录。

## 4. 维度一：蒸馏质量（distillation_quality）

[distillation_quality.py](../src/evaluation/distillation_quality.py) `evaluate()`。对每条记录：学生贪婪推理 → 与教师标签逐项对比。以下逐指标说明。

### 4.1 closed_answer_match_rate（闭集答案精确匹配率）

- **定义**：闭集样本中，学生 `[Answer]` 抽取的短答案 == 教师短答案（`hard_label.answer`）的比例。
- **计算**（[distillation_quality.py:139-142](../src/evaluation/distillation_quality.py#L139)）：
  - 学生短答案 = `extract_student_answer(out)`（[§7.1](#71-答案抽取)）
  - `score_match(out, t_short, is_open=False)` → 归一化后 `s == g`
- **公式**：`closed_match / closed_total`
- **解读**：最直接的硬指标。学生能否精确复现教师答案。**这是衡量蒸馏是否成功的首要指标**（治本重训后 ~0.82）。

### 4.2 closed_primary_match_rate（primary_answer 一致率）

- **定义**：闭集样本中，学生短答案归一化 == `soft_label.primary_answer`（教师软标签 argmax）的比例。
- **计算**（[distillation_quality.py:143-148](../src/evaluation/distillation_quality.py#L143)）：`normalize_for_match(s_short) == normalize_for_match(pa)`
- **与 4.1 区别**：4.1 对 `hard_label.answer`（硬标签 GT），4.2 对 `primary_answer`（软标签 argmax）。两者通常一致；不一致时反映教师软标签 vs 硬标签的口径差。

### 4.3 open_text_similarity / open_text_semantic_similarity（开集文本相似度）

开集样本，学生推理段 vs 教师推理段（`cot_reasoning.reasoning_paragraph`）的相似度，两个口径：

| 指标 | 计算方式 | 优缺点 |
|---|---|---|
| `open_text_similarity` | **词级 Jaccard**（[§7.2](#72-token-overlap)）：`|A∩B| / |A∪B|` | 严格，同义不同词得 0；偏保守 |
| `open_text_semantic_similarity` | **Sentence-BERT 余弦**（[§7.3](#73-语义相似度-sbert)）：all-MiniLM-L6-v2 句向量点积 | 补 Jaccard 盲区，同义得高分；更贴近"语义对不对" |

- **计算**（[distillation_quality.py:150-156](../src/evaluation/distillation_quality.py#L150)）：`s_rp = extract_student_reasoning(out)`，`t_rp = teacher_reasoning(rec)`，分别算 token_overlap 和 SBERT 余弦。
- **解读**：开集没有唯一正确答案，用相似度衡量。SBERT 通常比 Jaccard 高很多（如 0.81 vs 0.32），证明学生推理语义正确、只是用词不同。

### 4.4 cot_similarity / cot_semantic_similarity（CoT 相似度）

- **定义**：**所有样本**（含闭集）学生推理段 vs 教师推理段的相似度。与 4.3 同两种口径（Jaccard / SBERT），但 4.3 只统计开集，4.4 统计全集。
- **计算**（[distillation_quality.py:158-164](../src/evaluation/distillation_quality.py#L158)）。
- **解读**：衡量学生有没有学到教师的"推理过程"而非只抄答案。

### 4.5 answer_sequence_ce（序列交叉熵）

- **定义**：学生对**教师目标文本**的自回归负对数似然（NLL）。把教师的 `[Reasoning]...[Answer]...`（或开集 reasoning_paragraph）作为学生要预测的 token 序列，学生单次 forward，算目标段每个 token 的平均 NLL。
- **计算**（[evaluator.py:155-211](../src/evaluation/evaluator.py#L155) `sequence_ce`，合并版 [evaluator.py:263-269](../src/evaluation/evaluator.py#L263)）：
  1. `prompt_text` = chat template(question + image)
  2. `full_text` = prompt + 教师目标文本（`build_target_text(rec, "cot")`，[§7.4](#74-目标文本构造)）
  3. 一次 forward 得 `logits [L, V]`
  4. **next-token 对齐**：位置 `i` 的 logits 预测 token `i+1`。目标 token 区间 = `[prompt_len, total_len)`，由 `[prompt_len-1, total_len-1)` 的 logits 预测
  5. `logp = log_softmax(logits)`（**T=1，不温度缩放**）
  6. `nll = -logp.gather(target_ids)`；`ce = nll.mean()`
- **分桶**：闭集 / 开集分别累计（`ce_sum[bucket] += ce_val * n_tok`），最后 `ce_mean = ce_sum / ce_tok`（按 token 加权平均）。
- **公式**：`CE = -(1/T) Σ log P(token_i | context)`，T=1
- **解读**：**越低越好**。衡量学生对教师目标序列的似然，是工业更常用的蒸馏质量度量（替代 next-token 分布 KL，开闭集均适用）。推理阶段强制 T=1，与训练阶段"师生同 T"解耦——这里测的是学生在原始尺度下对教师目标的似然。

### 4.6 closed_distribution（软标签分布匹配）

**仅闭集**且有 `answer_distribution` 的样本。在"答案 token 位置"抽取学生对候选集的分布，与教师软标签比较。这是训练侧 KL 蒸馏在评估侧的可观测性回填——判断学生学到的是分布形状还是仅 top-1。

#### 计算流程（[evaluator.py:271-313](../src/evaluation/evaluator.py#L271)）

1. **候选 token 映射**（`_candidate_token_ids`，[§7.5](#75-候选-token-映射与跳过规则)）：把教师 `answer_distribution` 的答案字符串 → 首个 token id（单 token 才接受），归一化概率。
2. **定位答案 token**：`short_answer` 首 token 在 response 内**最后一次**出现的位置 `answer_pos`。
3. **抽学生分布**：`pred = logits[answer_pos - 1, :]`（预测 answer_pos 的 logits），取候选 token 子集 `cand_logits`。
4. `log_s = log_softmax(cand_logits / T)`，`s_probs = softmax(cand_logits / T)`（T=1）。
5. 三指标：
   - **`kl_mean`**：`KL(teacher || student) = Σ t*(log t − log s)`（按样本平均，[evaluator.py:294](../src/evaluation/evaluator.py#L294)）
   - **`cosine_mean`**：`cosine_similarity(s_probs, t_probs)`
   - **`top1_distribution_match_rate`**：学生 argmax == 教师 argmax 的比例
6. 附带 `student_distribution` / `teacher_distribution`（候选→概率，detail 诊断用）。

#### 跳过规则（`skipped`）

以下情况 `dist_res=None`，计入 `skipped`（[evaluator.py:316-349](../src/evaluation/evaluator.py#L316)）：
- **多 token 候选**：某候选答案编码 >1 token（如 "left lane"、"splendor and suzuki"）→ 返回 None
- **token 冲突**：两个候选映射到同一 token id
- **概率和 ≤ 0**
- **矛盾跳过**：教师 soft argmax（`primary_answer`）≠ hard 答案（`short_answer`）→ 视为软标签不可信，返回 None（**镜像训练侧 `_build_kl_meta` 的跳过口径**，避免 color 题"学生正确 vs 教师错"的高 KL 误导评估）
- **定位失败**：`short_answer` 首 token 不在 response 里，或位置越界

#### 解读

| 指标 | 方向 | 说明 |
|---|---|---|
| `kl_mean` | 越低越好 | 学生分布逼近教师的程度（0 = 完全一致） |
| `cosine_mean` | 越高越好 | 分布形状相似度（0~1） |
| `top1_distribution_match_rate` | 越高越好 | 候选集内 argmax 一致率 |
| `skipped` | — | 不可计算样本数（多 token/冲突/矛盾）；skipped 偏高不影响硬指标，但会缩小分布统计样本 |

> **历史背景**：旧版用 logprob 软标签时 color 题 "other" 候选虚高为 primary，经 KL 通道泄漏，学生塌缩到 "[Answer] other"。`矛盾跳过` 是当时的止血措施；治本（采样法 / 32B top-k logits 软标签 color 干净）后 skipped≈0、不再触发。详见 [docs/EVALUATION_REPORT.md](EVALUATION_REPORT.md) §4.5。

### 4.7 scenario_buckets（场景分桶绝对准确率）

学生 vs 记录自带 `ground_truth`（人工 GT）的绝对准确率，按 `question_type` 模板分桶。

- **分桶**（`_classify_scenario`，[distillation_quality.py:37-61](../src/evaluation/distillation_quality.py#L37)）：按 question_type（回退 question 文本）分到 `yes_no / counting / color / choice / open / other`
  - "how many" → counting；"color/colour" → color；"none of the above/multiple choice" → choice；"is/are" 开头 → yes_no；"what/where/who/which/why" 开头 → open
- **匹配**（[distillation_quality.py:127-136](../src/evaluation/distillation_quality.py#L127)）：`score_match(out, gt, is_open=(bucket=="open"))`
- **输出**：`overall_accuracy` + 各桶 `{correct, total, accuracy}`，按 total 降序
- **解读**：这是**对学生绝对能力的度量**（不是 vs 教师）。分桶能定位短板，如治本重训后 open 0.537、counting 0.724 是最弱项。

### 4.8 detail（分层抽样详情）

按题型分桶各取等量样本（`detail_samples // 5`，默认覆盖 color/counting/choice/open/yes_no 五类，达 10 条），每条含：
- `image_path` / `question_type` / `bucket` / `question`
- `teacher_answer` / `student_answer`（短答案）
- `teacher_output`（教师目标文本 `[Reasoning]...[Answer]...` 完整）
- `student_output`（学生生成**完整**文本，不截断）
- `teacher_soft_label`（`answer_distribution` {答案:概率}）
- `student_soft_label`（学生候选分布，或 null——见 [§4.6 跳过规则](#跳过规则skipped)）

> `student_output` 曾因 `out[:200]` 被截断，已修为完整输出（[distillation_quality.py:203](../src/evaluation/distillation_quality.py#L203)）。

## 5. 维度二：驾驶场景（driving_scenario）

[driving_scenario_eval.py](../src/evaluation/driving_scenario_eval.py)。**默认 disabled**。

与维度一的 `scenario_buckets` 区别：本维度用 `GTResolver` 从 COCO 标注文件（`v2_mscoco_{split}_questions.json` + `v2_mscoco_{split}_annotations.json`）按 `(image_id, question)` 查 `multiple_choice_answer` 作为 GT，桶映射用 `SCENARIO_BUCKET`（yes_no→negation_safety 等）。

**何时启用**：当评估记录**没有**自带 `ground_truth` 字段、需要回源 COCO 官方标注时。本项目记录自带 GT，故默认关、用维度一的 `scenario_buckets` 即可。

## 6. 维度三：部署效率（deployment_efficiency）

[deployment_efficiency.py](../src/evaluation/deployment_efficiency.py)。测量学生部署相关指标。

| 指标 | 计算 | 说明 |
|---|---|---|
| `total_parameters` / `trainable_parameters` | `sum(p.numel())` / `sum(p.numel() if requires_grad)` | 全量 / 可训练参数（merged 后 trainable=total） |
| `model_dir_size_mb` | 递归 `os.path.getsize` | 模型目录磁盘占用 |
| `peak_vram_gb` | `torch.cuda.max_memory_allocated / 1024^3` | 推理 `benchmark_samples` 后的峰值显存 |
| `avg_latency_seconds` | `mean(latencies)` | 单样本平均延迟（贪婪生成，含 `torch.cuda.synchronize`） |
| `median_latency_seconds` | `sorted(latencies)[n//2]` | 中位数延迟，抗离群点 |
| `throughput_samples_per_second` | `n / sum(latencies)` | 吞吐 |

- **benchmark_samples**：默认 50（10 样本方差过大不可靠）。
- **计时**：每样本前后 `torch.cuda.synchronize()`，排除异步 kernel 干扰。

## 7. 指标计算细节（共享工具）

[_common.py](../src/evaluation/_common.py)。

### 7.1 答案抽取

- `extract_student_answer(text)`（[_common.py:33](../src/evaluation/_common.py#L33)）：取 `[Answer]` 标记后第一行（保留多词如 "around fire hydrant"）。无标记返回空串（开集自由文本无可靠短答案，不回退首词法——首词几乎必为 "The/a/an" 会误判）。
- `extract_student_reasoning(text)`（[_common.py:53](../src/evaluation/_common.py#L53)）：取 `[Reasoning]` 与 `[Answer]` 之间内容；仅有 `[Reasoning]` 取其后；仅有 `[Answer]` 返回空；无标签返回原文。

### 7.2 token_overlap（词级 Jaccard）

[_common.py:96](../src/evaluation/_common.py#L96)：
```
sa = set(normalize_for_match(a).split())
sb = set(normalize_for_match(b).split())
overlap = |sa ∩ sb| / |sa ∪ sb|     # 两空集=1.0，一空=0.0
```

### 7.3 normalize_for_match（答案归一化）

[_common.py:18](../src/evaluation/_common.py#L18)：VQA 风格——小写、去冠词(a/an/the)、去标点、数字↔英文词统一（`normalize_answer(a, "word")`，如 "2"↔"two"）。用于所有答案精确匹配。

### 7.4 目标文本构造

`build_target_text(rec, "cot")`（[distill_dataset.py:113](../src/training/distill_dataset.py#L113)，评估复用训练侧）：
- **闭集**：`[Reasoning] {reasoning_paragraph}\n[Answer] {short_answer}`（有推理）或 `[Answer] {short_answer}`
- **开集**：`[Reasoning] {reasoning_paragraph}\n[Answer] {answer}`（统一两段式，消除标签泄漏）

序列 CE 用此文本作为学生要预测的目标。

### 7.5 候选 token 映射与跳过规则

`_candidate_token_ids`（[evaluator.py:316-349](../src/evaluation/evaluator.py#L316)）+ `_first_token_id`（[evaluator.py:63](../src/evaluation/evaluator.py#L63)）：
- 候选答案 → `tokenizer.encode(" "+answer)`，**长度==1 才接受**（单 token）
- 多 token / 冲突 / 概率和≤0 / soft argmax≠hard → 返回 None（跳过）
- **镜像训练侧 `DistillDataset._build_kl_meta`**，保证评估侧候选映射与训练侧 KL 完全一致

### 7.6 语义相似度（SBERT）

[_common.py:140-181](../src/evaluation/_common.py#L140)：all-MiniLM-L6-v2（经 `HF_ENDPOINT=https://hf-mirror.com` 下载），句向量 L2 归一化后点积 = 余弦相似度。懒加载缓存；加载失败则降级跳过（不阻断评估，对应指标为 null）。**批量编码**（循环后一次性 encode + 矩阵点积），避免逐条 encode 开销。

## 8. 训练—评估口径一致性

评估侧刻意**镜像训练侧**的若干逻辑，保证"训练优化的目标"与"评估测量的对象"对齐：

| 训练侧 | 评估侧镜像 | 作用 |
|---|---|---|
| `DistillDataset._first_token_id` | `evaluator._first_token_id` | 候选答案 → 单 token id 映射一致 |
| `DistillDataset._build_kl_meta`（候选+跳过） | `evaluator._candidate_token_ids`（含矛盾跳过） | KL 通道的候选集与跳过样本一致 |
| `DistillDataset._norm_ans` | `evaluator._norm_ans` | KL 矛盾判定的答案归一化一致 |
| `build_target_text` / `get_closed_meta` | 评估直接 import 复用 | 序列 CE 目标文本与训练目标同源 |
| `max_pixels` 对齐 | 评估强制设同值 | 视觉 token 数一致，分布不失真 |

> 这意味着：训练时被 KL 跳过的样本，评估时也在 `closed_distribution.skipped` 里跳过；训练时纳入 KL 的候选 token，评估时用同一组候选测分布匹配。口径不一致会让指标失真，此处已对齐。

## 10. 指标速查与解读

| 指标 | 维度 | 方向 | 含义 | 健康参考 |
|---|---|---|---|---|
| `closed_answer_match_rate` | 蒸馏质量 | ↑ | 闭集学生答案==教师 | >0.80 |
| `closed_primary_match_rate` | 蒸馏质量 | ↑ | 闭集学生==教师软argmax | ≈ match_rate |
| `open_text_semantic_similarity` | 蒸馏质量 | ↑ | 开集推理 SBERT 余弦 | >0.75 |
| `cot_semantic_similarity` | 蒸馏质量 | ↑ | CoT SBERT 余弦 | >0.75 |
| `answer_sequence_ce.closed/open` | 蒸馏质量 | ↓ | 教师目标序列 NLL | 越低越好 |
| `closed_distribution.kl_mean` | 蒸馏质量 | ↓ | 师生分布 KL | <0.05 |
| `closed_distribution.cosine_mean` | 蒸馏质量 | ↑ | 分布余弦 | >0.99 |
| `closed_distribution.top1_match` | 蒸馏质量 | ↑ | 候选 argmax 一致 | >0.99 |
| `scenario_buckets.overall_accuracy` | 场景 | ↑ | 学生 vs 人工GT | >0.80 |
| `peak_vram_gb` | 部署 | ↓ | 峰值显存 | <12GB(本地) |
| `avg_latency_seconds` | 部署 | ↓ | 单样本延迟 | 视场景 |

### 解读要点

- **硬指标优先看 `closed_answer_match_rate`**（学生能否复现教师答案）。它高而 `cot_similarity` 低 = 学生抄对答案但推理不像；两者都低 = 蒸馏失败。
- **`semantic` 相似度 > Jaccard 相似度** 是常态（同义不同词），证明语义正确。Jaccard 低不必惊慌。
- **`closed_distribution` 看分布形状**：KL 低 + cosine 高 = 学生学到了教师的置信度分布，不只是 argmax。`skipped` 高不影响硬指标，但缩小分布统计样本——多 token 候选（开集式答案）是主因，设计使然非 bug。
- **`scenario_buckets` 看短板**：按题型定位弱项（如 open/counting 偏低），指导后续数据配比或训练策略调整。
- **`is_heldout=false` 时所有指标高估**（回退训练集评估），报告会告警；正式评估务必用 held-out 集。

## 11. 常见问题

**Q: `student_soft_label` 为 null？**
A: 该闭集样本被 `closed_distribution` 跳过——多 token 候选 / token 冲突 / 教师 soft argmax≠hard / 答案 token 定位失败。设计使然，与训练侧 KL 跳过同口径。单 token 答案（是/否、颜色、数字）会得到完整分布。见 [§4.6 跳过规则](#跳过规则skipped)。

**Q: 蒸馏质量 vs 场景准确率区别？**
A: 蒸馏质量（§4.1/4.2）是学生 vs **教师**（学生学到教师没有）；场景准确率（§4.7）是学生 vs **人工 GT**（学生绝对对不对）。教师本身不是 100% 正确，所以学生可以"match 教师"但"不如 GT"，反之亦然。`retention = overall_accuracy / teacher_accuracy` 衡量学生保留了多少教师能力。

**Q: 评估和训练的 KL 为什么口径必须一致？**
A: 训练 KL 跳过的样本若评估不跳过，会出现"学生正确、教师软标签错"的高 KL，拉低指标误导判断。镜像跳过（§8）消除这种噪声。

**Q: 32B 实验和 agent_distill 实验的评估有何不同？**
A: 评估流程完全相同。区别仅在 `eval_data_path` 指向的软标签来源不同（32B top-k logits vs agent_distill sampling/logprob），以及 `train_data_path` 训练数据不同。详见 [docs/EVALUATION_REPORT.md](EVALUATION_REPORT.md) §0.5 两版对比表。
